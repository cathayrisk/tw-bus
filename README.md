# tw-bus

大臺北公車的站牌到站看板。預設站牌是新北板橋公車站，追蹤 307 與 265 兩個路線家族。

開啟後可加到手機主畫面，會以全螢幕啟動。

## 它跟一般公車 App 的差別

- **每一台車各自一列**，不是每條路線只給一個數字。307 常常連著來三台，看板會把每一台的到達時間分開列出來，也看得到後面的空窗有多長。
- **路段壅塞**用公車自己當探針推算。格子以「地理網格（約 400m）＋行進方位（8 象限）」為鍵，不綁路線，所以跑同一條路的不同路線會累積到同一格；對向車道方位不同仍然分開。方位取自路線線型走向，不用車輛回報的 Azimuth（停車時可能是 000）。
  每格每台車只投一票，值是該車實際通過這一格的速度（里程差÷時間差），所以卡住的車票數仍是 1、但那一票的值會隨著卡越久而越低。近 30 分鐘中位數低於 4 km/h 標紅、低於 12 km/h 標橙，每格至少要 3 台車才判定。
  實測：改用共用格之後達標率由 18% 升到 33%、每格平均車數由 1.6 升到 2.32。資料存在瀏覽器 localStorage，需要累積幾分鐘。
- **地圖預設收起**，因為看板已經把答案講完了。需要看來車位置與壅塞段落時再展開；展開時只畫來車到你之間那一段路廊，沿途小圓點是還沒到的站。

## 哪些數字是資料、哪些是推估

資料源的預估到站只提供「距該站最近一台車」的時間，第二台之後官方沒有給。所以：

- 標 **官方** 的是資料源直接給的。
- 標 **推估** 的是本頁自己算的（固定 11.5 km/h ＋ 60 秒），實測誤差中位數 27–114 秒，畫面上寫 ±1–2 分。尖峰時段未驗證。
- 官方時間跟最近那台車推不出合理速度時，該列會標 **未指認**，只顯示官方數字，不指認車輛。

## 資料來源

臺北市公共運輸處 公車動態資訊系統，經 Data.Taipei 開放，端點為
`https://tcgbusfs.blob.core.windows.net/blobbus/`，每 10 秒更新。

只涵蓋臺北市轄的聯營公車路線。新北市轄路線（793、245、藍37 等）不在這個資料源，需要改接 TDX。

## 換路線

編輯 `index.html` 最上方的 `TRACK` 陣列，再按畫面上的「重抓路線圖資」。
